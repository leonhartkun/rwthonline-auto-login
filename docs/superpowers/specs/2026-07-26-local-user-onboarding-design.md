# RWTHonline 本地用户初始化设计

## 目标

让任意 RWTH 用户从 Chrome 网上应用店安装扩展后，无需安装原生助手，即可在首次使用时输入自己的 RWTH 账号和密码、从本地选择自己的 TOTP Token 二维码图片完成初始化，并在 RWTH 页面自动登录。

## 用户流程

1. 用户点击扩展图标；未完成设置时进入“初始化”页。
2. 用户填写 RWTH 用户名和密码，并选择本地 Token 二维码图片。
3. 扩展仅在本机解码二维码中的 `otpauth://totp/...` 信息，校验其包含可生成 TOTP 的密钥。
4. 用户确认保存；扩展将用户名、密码和 TOTP 密钥写入当前 Chrome 配置文件的本地扩展存储。
5. 在受支持的 RWTH 登录页，扩展自动填写凭据、选择 Selfload Token、生成并填写当前 TOTP 码。
6. 用户随时可打开设置页更新凭据、重新导入二维码或删除全部本地数据。

## 架构

- `onboarding.html` 和 `onboarding.js` 提供首次设置与编辑界面；二维码从用户选择的本地文件读取，不请求相机权限，也不上传。
- `totp.js` 是不依赖服务器的 TOTP 与 `otpauth` URI 解析模块；它由初始化页校验二维码结果，并由后台脚本生成当前验证码。
- `credential_store.js` 只负责读写 `chrome.storage.local` 中的凭据，提供缺失配置检查和清除操作。
- `background.js` 不再使用 Native Messaging，而是从本地存储读取凭据并生成 TOTP。
- `content_script.js` 保持只与 RWTH 页面交互；日志不再把页面中的不可信文本作为 HTML 注入弹窗。

## 数据与隐私边界

- 用户名、密码和 TOTP 密钥只保存在用户本机的 Chrome 扩展本地存储中；不使用同步存储、不发送网络请求、不运行分析或遥测。
- 扩展不能承诺操作系统级的加密保险库；设置界面和商店隐私披露必须明确说明本地存储的范围。
- 二维码中不含 `otpauth://` URI、缺少 `secret`、或包含不支持的哈希算法时，初始化失败并保留用户已填写的非秘密表单状态。

## 商店交付物

- Manifest 删除 `nativeMessaging` 权限与固定开发者密钥，最小化权限并更新版本、名称、英文商店描述。
- 准备商店描述、隐私政策、截图需求清单和打包前检查清单。
- 发布前由拥有 Google 账号与付款方式的发布者在 Chrome Web Store Developer Dashboard 完成一次性注册、付款、身份或商家验证（若控制台要求），上传 ZIP 并提交审核。

## 验收标准

- 新用户无需原生主机即可完成初始化。
- 本地选取有效 Token 二维码可生成符合 RFC 6238 的 TOTP。
- 凭据缺失时不会自动尝试登录，并会引导用户打开初始化页。
- 删除数据后自动登录立即停止。
- 商店 ZIP 不含私钥、日志、原生主机或用户凭据。
